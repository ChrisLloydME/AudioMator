# Independent acceptance of AudioMator audit remediation

**Temporary campaign review specification · 2026-11-18**

Review the candidate against the [implementation specification](REMEDIATION_IMPLEMENTATION.md) and the original [audit](../Engineering/AUDIOMATOR_INDEPENDENT_AUDIT_2026-11-18.md) with its [reproduction evidence](../Engineering/AUDIOMATOR_INDEPENDENT_AUDIT_EVIDENCE_2026-11-18.md). The implementer’s assertions and evidence are inputs to the review. An independent reviewer owns the disposition. The maintainer owns any later release decision. Remove this checklist and implementation handoff after acceptance, preserving a dated acceptance record with the actual candidate, executed probes, dispositions, and limitations.

## Set up a defensible comparison

1. Record audited baseline commit and dirty-catalog patch from the evidence companion. Build an isolated baseline if a test runs on the old APIs. Otherwise port only the probe or introduce a targeted fault in a separate candidate copy, retain the exact diff, and show that the oracle catches it. Keep implementation and test source outside the original workspace for experiments. Use disposable media, fake providers, and temporary directories. Keep the pinned published TagLibAudioMetadata 0.8.1, normal Xcode resolution, stable Xcode and an isolated `.deriveddata-codex` under each tested copy. No package cache or checkout edits, local package candidate, real music library, manual launch, UI automation, or screenshots.
2. Freeze the candidate under review. Record branch, HEAD, index and unstaged diff and hashes of any additional inputs. Match the toolchain, package resolution revision, and candidate identity in submitted logs. Changes after baseline or candidate identification require a new record and affected rerun. Compare staged/unstaged/untracked state after probes and isolate all fault injection from the candidate.
3. Trace each path in the matrix below from the production command or view callback to intent, admission, commit and publication. Inspect unrelated paths named in the implementation scope. When reviewing coverage, compare the actual code exercised to the test setup or fake. Require a preserved before-state plus exact after-state for disk cases. A test that records only a writer call, prepared string, warning text, or named test execution is inadequate evidence for a disk guarantee.
4. For safety failures use a byte digest and, as applicable, an independently specified raw property map, native field array, file identity, and sound content check. Use pinned package public/raw readers or an independent parser for the observation, never derive expected values from the production planner. For representative FLAC or WAV, verify unchanged audio with the package's public content identity where supported or independently decoded PCM; a metadata-only byte digest can change legitimately on successful edits. For rejected writes check full data bytes plus no retries. For rename check identity as well as basename and bytes.
5. Run the integrated unfiltered gate, independently inspect warning output and named tests, and check documentation. Record native and performance evidence separately. Defer unsupported platform or signed-distribution claims to the maintainer. Compile success and a green suite are preliminary evidence.

## Equivalent paths and boundary audit

- **Strict authority.** For semantic providers, filename extraction, CSV/TXT and field transfer, renumber, MuseAmp, erase and LRCLIB, collect one inspected flow showing captured plan fields, path, fingerprint, version and logical ID used at the coordinator/adapter. Change only expected version, only fingerprint, source membership, or protection state. Confirm old plans fail and freshly reviewed plans work. For a no-op and an unsupported format confirm preflight makes zero mutation calls. Verify the actual writer cannot substitute the latest model’s version or request nil. Read-only paths and rename itself have separate identity contracts. Check that Inspector and Raw retain ordinary require-reload, safe merge and prefer-disk behavior, even with package audio identity absent. Confirm no regression to dates, unrelated fields, totals, metadata arrays or per-file warning counts.
- **Actual consumers.** Search for all call sites of `persistMetadataEdit`, `executeMetadataFileMutation`, `withUpdatedURL`, `updateEditForSelection`, `applyLRCLIBSyncedLyrics`, `openMetadataEditor`, `albumDetail`, and `make*Plan` equivalents. Compare to the implementation inventory. Trace new wrappers too. Confirm any remaining permissive adapter arguments are low-level tests/contracts or protected under policy-specific logic. In every strict workflow a target cannot gain authority by reassignment/reload without a newly visible review. In every filesystem writer authority covers directory access through the whole operation.
- **Irreversible operations.** Check journal bootstrapping authority, scopes, exclusive syscalls, actual directory entry identity, durable ordering, filename normalization, access teardown, and conflict rules. Inspect all destructive paths that can create, update, delete or use journals. A malformed or old journal never commands blind path mutation. File recovery scope is recorded and explicitly approved after restart. Automatic reconciliation only observes.
- **Evidence credibility.** For each matrix row require a demonstrated red baseline, safe isolated mutation or another independent observable failure mode; use a small outside canary for pure functions. Review old named tests whose expectations intentionally change and rerun all others. A removed false assertion must be replaced by one that reaches the previously missed production boundary. Check every relevant preservation invariant in tested state or persisted readback. Exclude wall-clock estimates from the correctness gate except bounded test safety timeouts.

## Run and record

Follow [Verification commands](REMEDIATION_IMPLEMENTATION.md#verification-commands) with a fresh disposable candidate checkout. Run direct strict Debug resolution/build and a real forced wrapper invocation, then the normal unfiltered named gate:

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
git rev-parse HEAD
git --no-optional-locks status --porcelain=v2 --branch --untracked-files=all
bash scripts/validate-release.sh
python3 scripts/check-doc-links.py
git diff --check
```

Inspect `source.txt`, `core-gate.json`, `test-gate.json`, test summary and named tree, `.xcresult`, and build and artifact logs in the resulting `.deriveddata-codex/Validation/…` directory. Require successful policy tests, exact current source identities from both test targets, positive command statuses, and zero failures, skips, expected failures, missing or duplicate names. Confirm normal pinned package resolution, the unsigned artifacts' declared deployment minima and both executable architecture slices with `lipo -archs`. A debug test filter, previously retained output, or `codex-build.sh` skip does not satisfy this gate. Run the implementation’s newly tracked Markdown through the checker and check anchors and affected current-state pages against the candidate. Separate app-hosted component assertions from anything not performed on installed or signed copies.

Write one dated record in Engineering and index it. Per AM finding record **accepted**, **failed**, or **blocked**, candidate baseline, expected and observed results, negative control or equivalent evidence, exact command or probe source and remaining limitations. Mark a blocked item with the particular missing evidence or required design decision. Require independent review of integrated code and all severe findings before recommending remediation completion. Reopen the package if any equivalent path can reintroduce a defect, if safety/compatibility changed without approval, or if passing evidence did not use the production path. Engineering acceptance is separate from signed App Sandbox/OS coverage, notarization, installation, device durability claims, and general release approval.
