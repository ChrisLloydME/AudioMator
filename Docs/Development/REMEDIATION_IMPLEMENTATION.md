## Decisions and preservation

The maintainer approved three product choices on 2026-11-18. Track Renumber requires a start of 1 or greater, drops the zero-padding control, and previews numeric stored values. Leaving the LRCLIB view or closing its window cancels requests and unstarted writes, with accurate reporting for any commit already underway. Apply also cancels on replacement of the session. Section-level edge cases specify how those decisions interact with existing compatibility.

Preserve Swift 5 language mode with complete strict concurrency and MainActor default isolation, the macOS 15 minimum, signed sandbox intent, the exact Xcode package pin, localized user strings, additive per-file summary buckets, policy-driven Inspector/Raw conflict behavior, and the existing separation between durable commit and reload or durability warnings. Existing TagLib verified writes remain exclusively behind `AudioMetadataPipeline`. The package mapping contract, I/O behavior, independent native date identities, and known unsupported layouts remain in force. Preserve presentation UUID continuity and the single selection owner. An operation starting late, being cancelled, being successfully committed with uncertain durability, or failing to reload has a distinct outcome.

## Ownership and common contracts

### C1 · Bind reviewed writes to an observation and an intent

**Production seam.** The present `persistMetadataEdit(_:to:comparedTo:syncInspectorAfterReload:expectedFileFingerprint:expectedMetadataVersion:)` builds intent from a mutable/re-resolved `AudioFile`, selects a conflict path by optional arguments, and can default the expected package revision to the model currently loaded at the time of Apply. Replace this overload's mixed purpose with explicit strict and draft-conflict routes. The existing `FileMutationCoordinator`, `MetadataFileMutationExecutor`, per-file I/O, and `MetadataConflictResolver` remain the execution primitives. [Current persistence](../../AudioMator/Features/Main/ViewModels/AudioViewModel+MetadataWrite.swift) · [File executor](../../AudioMator/Features/Main/Application/MetadataFileMutationExecutor.swift) · [Pipeline protocol](../../AudioMator/Domain/MetadataEditing/AudioMetadataPipeline.swift)

Introduce in Domain/MetadataEditing an internal Sendable and Equatable `ReviewedMetadataTarget` with immutable `id: AudioFile.ID`, `url: URL`, `fingerprint: AudioFileFingerprint`, `version: MetadataFileVersion`. Expose a factory or failable initializer `init?(verified file: AudioFile)` that requires a file URL, both tokens, and no refresh-required flag. Capture from a single successfully read observation. A path rebind that retained a stale model or lightweight probes after failed load never creates a verified target. Keep the captured file URL as the authority, compare normalized identity with the existing volume-aware path helper where separately captured URLs may alias, and preserve the exact fingerprint and version. Session IDs or `snapshotID` may guard presentation but cannot substitute for either disk token. A refreshed observation with the same path, fingerprint and version can still satisfy the current target. A UUID reused for a different observation cannot. Separate app collection membership from this value. Do not encode provider request DTOs with local paths or revision fields.

Use a Sendable prepared write value in the application/domain boundary with the authorized target and an immutable, prevalidated semantic `MetadataEditPayload`, raw `RawMetadataPatch`, or erase intent. Prefer typed feature plans that carry this value alongside presentation metadata. The payload is computed from the reviewed observation. It must have an independently testable exact set of executable field changes, including component operations, and share normalization/validation with its preview. Use adapter-owned projection for semantic capability preflight and commit. Add an internal Sendable projection summary (effective field operations plus validation outcome) where a planner needs preview truth. Package patch construction stays adapter-owned, so C1 retains the frozen app payload and obtains the same result through the same deterministic pure encoder at commit. Comparison and trimming happen before classifying an action as unchanged. Treat missing semantic capability information as unsupported for every requested field, correcting the current empty-set fallback in `unsupportedMetadataWriteFields`. If the requested set is empty it is a no-op. Preserve raw capability as a separately classified operation and the narrower verified-format best-effort erase contract. Keep TagLib-specific encoding in the adapter and package types within existing allowed exceptions. If a throw occurs during projection or validation, publish a rejection and make zero package write calls. A legitimate unchanged edit produces no write and preserves bytes. Never substitute the latest editor model or fabricate a revision to keep a row actionable.

Execution order for strict routes:

1. At plan creation, classify missing/recovery-required snapshots, duplicate targets, invalid intent, and unsupported fields as ineligible before any authorization prompt. Allow an unavailable target to be shown for search/preview with a clear reason. Do not create a writable entry.
2. Resolve current membership by ID and captured URL from F3’s source index, then apply the workflow’s existing eligibility scope. A sidebar or session change that removes a target from that scope cannot authorize a new write through a surviving hidden membership. Authoritative post-commit publication uses the source index regardless of presentation. Ensure the model is available and satisfies both reviewed tokens and recovery state. Take prompts against captured eligible URLs on MainActor only. Retain required scopes for the operation. A modal authorization or await cannot confer new authority. Keep the no-new-write rules for a dirty Inspector session where already required.
3. Acquire the captured path through the existing coordinator. After queueing, revalidate current app membership, URL and protection state on MainActor, and verify the captured fingerprint in the detached file body. Pass the **captured nonoptional package version** to the adapter. Reject a stale current app observation before invoking a writer. If only the disk changed and the final guard is the package comparison, require the package rejection to leave bytes unchanged. A mismatch must fail, including an external writer in the final window covered by the package's compare-and-commit. Avoid an extra metadata reread solely to get a replacement version. Recipient resolution, coordinator recheck, and any commit admission require the same target. Keep the synchronous commit and bounded readback semantics.
4. Publish a returned observation to the authoritative source collections and defer or throttle visible rebuilds as appropriate. Tag the completion with the owning operation/draft generation. Preserve cancellation, committed, committed-with-warning, and failure outcomes in original plan order. A cancelled client can suppress stale UI updates while still delivering real disk outcomes to the operation summary.

### C2 · Operation lifetime, publication, and reservations

Separate a reviewed plan from the current presentation. Keep `AudioViewModel` as selection owner. File source observations, including accepted post-mutation observations, update collections by file identity regardless of sidebar visibility. A store owns its displayed session and generation. An app operation owns its real summary and mutation lifecycle. Capture a session/draft generation at entry and recheck after every suspension before publishing UI or scheduling the next write. Keep revision checks under the common path reservation and state changes on MainActor. Use existing workbench operation tokens and cancellation where adequate. Use a scoped draft owner in F3 and a session operation owner in N1. Ownership stays per workflow, without a global broker or a parallel selection model.

Preserve current per-file ordering, meaningful independent concurrency and pending reload flush behavior. Begin/end shared progress only with a matching operation token or no ownership at all. Thread an explicit `.cancelled` outcome through `MetadataWriteExecutionResult` and its callers instead of mapping it to `.failure(MetadataCancellation.message)`; adapt batch buckets and single cancellation presentation without losing existing genuine errors.

In `MetadataFileMutationExecutor`, use a per-target `MetadataCommitPermit` with states `pending`, `revoked(reason)`, and `admitted`. Use `OSAllocatedUnfairLock` or the existing equivalent lock pattern. Expose synchronous `revoke(reason:)` and `admit() -> AdmissionResult` that serialize the first transition out of pending. When the MainActor owner rechecks target eligibility under the reservation, register the permit in a small map keyed by file ID and operation. Remove it on operation exit. Revoke it synchronously on removal from eligible membership, incompatible observed revision, recovery-state invalidation, superseded write session where cancellation is required, or revoked scope. Do not revoke for republishing the same reviewed observation. Conflict-aware drafts remain eligible for their documented policy-driven merge when only the current revision changes. They use the same permit for membership, protection, and cancellation. A revoked permit records precommit cancellation for a cancellation reason and an eligibility failure for a stale or blocked reason.

Install a caller-side `withTaskCancellationHandler` before launching the detached worker. Cancellation synchronously revokes its permit. After verifying disk fingerprint and immediately before the synchronous writer call, the worker admits pending or returns its recorded rejection. The worker does not inherit the caller's cancellation. Keep the reservation through admitted commit and bounded readback, including warnings. The permit’s critical section contains no file or actor work. Test cancellation and removal/protection between the final MainActor check and admission, as well as cancellation inside the admitted writer. Include an equal-revision refresh control. Cancellation consumes no unstarted intent. It cannot cause a committed outcome to be retried or relabeled as a pre-commit cancellation. Do not rely on view-level overlays or toolbar disablement as the sole guard. Any actor or callback used for off-main planning must receive immutable Sendable inputs, avoid UI types, and discard results by generation. Capturing a live mutable collection across an await is not a snapshot.

Record the new shared reviewed-operation and publication boundary in a single ADR when C1/F3 lands. Record journal/restart rules in a separate ADR with F2 because they change durable filesystem recovery semantics. Select the next free ADR numbers at implementation time and link the existing ADRs on selection ownership, reservation, adapter isolation and exchange ownership. Update current architecture docs with implemented behavior in the same phase.

## File identity, recovery and source work packages

### F1. Preserve metadata provenance after a rename · AM-03

**Acceptance invariant.** A file can authorize metadata writes only from a coherent observation of that file. Moving a display snapshot to another URL can retain its labels for navigation and recovery, but can confer no write authority. Metadata, conflict baseline, metadata version, fingerprint, operative URL, and logical ID must travel together from the same verified read. A later preview requires its own reviewed target. Keep the Inspector/Raw conflict policies and their pinned package commit guards. The strict target value used by Apply workflows is distinct from the older coherent baseline retained for an existing conflict-aware draft.

**Implementation ownership and sequence.**

1. In [AudioFile.swift](../../AudioMator/Domain/AudioFiles/AudioFile.swift) put the write-authorizing fields behind a single observation value or a narrow construction surface, so call sites cannot compose a new version and fingerprint with retained metadata. Make the successful construction route the validated read in [AudioFile+TagLibLoading.swift](../../AudioMator/Infrastructure/TagLib/AudioFile+TagLibLoading.swift). The loader already captures the fingerprint before the snapshot and checks again after AVFoundation awaits. Require the version to be present for a write-authorizing observation. Keep value projections available for display when authority is unavailable. Expose a purpose-built move/recovery projection which always clears write authority. Remove the general ability of production callers of `withUpdatedURL` to attach arbitrarily supplied safety fields. The two Quick Import/watched loader normalization branches in [AudioViewModel.swift](../../AudioMator/Features/Main/ViewModels/AudioViewModel.swift) should preserve the exact input URL supplied to the loader or verify a genuinely equivalent representation. Preserve lexical URLs and the corresponding access URL; a normalized equality key identifies an alias without conveying sandbox permission.
2. In `renameFiles(using:)`, carry a verified move receipt for each successful move or uniquely located failure recovery. Include the claimed ID, old URL, actual destination and filesystem entry identity observed at the end of the move. Do not read a moved file's contents to reconstruct the pre-move draft. Inside the existing source/destination reservation and directory access, publish the move's URL and refresh-required placeholder by stable ID before releasing the reservation. Publish swaps as one mapping update, clearing old keys before setting new ones. Immediately invalidate older scan epochs, import path tokens and pending model generations for affected identities. On an uncertain move, block the affected ID and paths while still reserved. Apply this to `reconcileRenameRecovery` as well as successful moves. Use the F3 source-membership reconciliation, independent of the visible sidebar.
3. Reacquire each destination path under the same coordinator for bounded full readback. Keep concurrent reads at the existing metadata-batch limit of four and start a 60-second read deadline only after acquiring that destination reservation. Hold access until each worker finishes with its lease. A timed-out worker cannot publish. Keep it counted against the live-read limit until it unwinds. If all lanes remain occupied by overdue reads, return unstarted targets as still refresh-required and let the user explicitly reload them. Timeout can cancel a read without promising that the underlying I/O has stopped. Keep the disk outcome independent of readback. Check the receipt's physical entry identity against the destination before the load and before accepting its result. A replacement or ambiguous location stays blocked pending explicit review. Use the move generation plus expected ID/URL and current pending move decision at MainActor publication. No application writer can use the placeholder in the gap because its recovery check runs inside its own reservation. Avoid holding a whole batch's source reservations while readback runs, and never nest a reservation for overlapping URLs. On full reload failure, retain the display projection and direct the user to explicit Reload from Disk. Remove the catch branch that reads just fingerprint/version and re-enables editing.
4. In `acceptFileObservation` and recovery state transitions, replace the Boolean bypass semantics of `explicitlyRecover` with named reasons. A receipt-matched rename readback clears only the temporary decision for that same move. A user-requested coherent reload may clear an earlier resolved-path failure after dirty-draft handling. If the read observes a successor at the same name, only an explicit acceptance of that replacement can authorize a new draft. An unknown-location journal decision (F2) survives normal reload until the journal identifies a verified location or the user explicitly resolves it. Watcher observations, automatic activation, quick reimport, and late pre-move reads can never clear either decision. Reject rename of a previously blocked source until an authorized coherent reload or recovery clears that decision. Tighten [FileRenameTemplate.swift](../../AudioMator/Domain/Rename/FileRenameTemplate.swift) so the planner cannot revive a blocked source by supplying a new stat-only fallback fingerprint.
5. Preserve rebase semantics in [MetadataConflictResolver.swift](../../AudioMator/Infrastructure/TagLib/MetadataConflictResolver.swift). Both equal-version fast paths can remain when original baseline and version share provenance. Add the new checks at mutation entry and again after acquisition in [MetadataFileMutationExecutor.swift](../../AudioMator/Features/Main/Application/MetadataFileMutationExecutor.swift) and the existing exceptional callers, with the final captured expected version passed to TagLib. `MetadataEditorStore.loadState` must attach a new raw baseline only from a coherent snapshot and accompanying validated fingerprint. A compatibility/mock path with missing authority may expose readable raw metadata but cannot make an unversioned production write. Keep test injectability by manufacturing coherent fake observations intentionally; a synthetic test model does not set the production authorization contract.

### F2. Make staged renames recoverable after interruption · AM-04

**Acceptance invariant.** After termination at any writable stage, a new process can find the exact recorded operation, explain the state, and offer an identity-checked restoration. A genuine completed-commit record preserves new names. Recovery performs no overwrite, including if an outside file appears at a chosen destination. No broad filesystem search, stale draft adoption, or automatic destructive repair is needed. Preserve case-only renames, swaps and cycles that pass the existing collision policy.

Use separate state values in memory for locations and errors. The record contains only information needed for recovery. Protect manifest I/O and live transaction ownership across processes of the same bundle container with a stable lock file in the journal directory and a nonblocking exclusive lock. Hold it from preflight through terminal manifest publication, and again for explicit Restore. The lock inode never moves with a manifest. If a second instance cannot acquire it during classification, show recovery as busy and provide a user-requested retry. Do not hold it while requesting folder scope. Separate containers and other programs remain external writers. The path records are user data and stay local. Prevent accidental disclosure in automatic logs and diagnostics. Retain malformed/unsupported journal records for manual inspection, with a sanitized warning. Treat persisted paths as input: validate same parent, unique stage names bound to the manifest UUID/index, intended extension and role collisions allowed only as actual swap/cycle relationships. Store receipt and recovery paths based on the lexical entry as moved, not the symlink-resolving lock/comparison key.

Use three service entry points over immutable input and injected filesystem and journal interfaces. `execute(prepared:)` returns committed move receipts, rolled back, or unresolved with an operation ID. `classify(_ manifest:)` returns current status and observed roles per entry without moving files. `restoreOriginals(_ manifest:)` returns restored or unresolved with the same operation ID and verified observed locations. The ViewModel owns authorization, reservations, presentation, and occurrence publication. The Infrastructure service owns durability and exclusive filesystem effects. Resolve prepared, committed, unreadable, and busy classification in the Folders surface before offering mutations.

**Create and commit.**

1. Choose the transaction UUID, deterministic per-index staging names and role paths before acquiring their union reservation.
