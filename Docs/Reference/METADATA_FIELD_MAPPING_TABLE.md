# UI, application, package and native metadata mapping

This is the single end-to-end lookup table for AudioMator's current metadata identities. Baseline: published [TagLibAudioMetadata 0.8.3](https://github.com/ChrisLloydME/TagLibAudioMetadata/tree/0.8.3), revision `ebd21c7b1aa9be607133fc4a9de02d2c7890f42f`; contract `AM-TLAM-MAPPING-2.2`. This is a documentation view of the existing implementation, not a new mapping policy or an expansion of Inspector fields. Field meanings as shown in the app are described in the [Metadata Field Guide](../Product/METADATA_FIELD_GUIDE.md).

## How to read the table

Start with the English UI label, then follow the same row through the application property, package enum case, semantic identity, engine keys and native storage. UI labels are localized at runtime. For fields without an Inspector row, the label is the package registry label used by Metadata Editor suggestions; it does **not** imply a dedicated control. Metadata Editor's actual rows use raw keys. Its suggestion list excludes artwork. "Optional" means configurable in Settings and disabled for a new installation; an existing preference can enable it. "Default" describes a new installation, not every user's saved configuration.

Application properties are on `AudioFile` and, when marked `model + draft`, also `SingleFileEditModel`. `containerValues` is internal model storage; it does not imply a visible container-fields Inspector section. A raw value map is the Metadata Editor/pipeline representation and has no dedicated scalar application property. Credits and technical properties are listed after the package rows because they are not extra `MetadataFieldKey` cases.

**Semantic keys, engine keys and native keys are different namespaces.** Engine keys are the registry's `propertyMapKeys` in declared order, including lookup aliases; they are not extra preferred native write locations. In particular semantic `DATE` is package `.standaloneDate`, while engine `DATE` can project `.year`. `STANDALONEDATE` is a registry projection identity, not an atom named STANDALONEDATE. Do not submit a semantic key as an arbitrary raw key and assume the same result. The raw editor preserves the selected raw surface; it is not a substitute for typed semantic editing.

Native cells below are **published registry registrations**, with their declared preferred targets and restrictions. A plain location does not certify a successful read/write for every file or every operation. Actual destination capability, observed tag version/layout, supported value kind and lossless verification must also pass. This document does not claim that all formats have been exhaustively tested. Read aliases implemented by bridge extraction/planning are not all represented in the registry and are not additional write targets; see [alias and preservation policy](../Architecture/METADATA_MAPPING_SPEC.md#5-read-precedence-aliases-and-preservation).

| Notation | Meaning |
| --- | --- |
| `F(K)` | Exact MP4 freeform `----:com.apple.iTunes:K`; a conventional extension, not a native four-character atom |
| `TXXX(K)` | ID3 user-text frame with description K; a conventional extension |
| `[number]`, `[total]` | Independent component of one shared track/disc/movement field |
| `[RO]` | Registered location, typed writes withheld |
| `[T−]` | Role-qualified registration; no supported high-level typed value kinds |
| `[P]` | Planned registration only; native implementation unavailable, not writable |
| `[X]` | Declared version-extension frame or extension text key |
| `—` | No registered target in this family; not permission to invent a fallback |

## File formats and tag surfaces

The columns describe **tag surfaces**, not filename-based guarantees. MP3/AAC/DSF/DSDIFF and WAV/AIFF may use ID3; select the actual tag version. WAV can also carry RIFF INFO: its INFO column is not a substitute for its ID3 column. AIFF has no RIFF INFO surface. FLAC and Ogg Vorbis/Opus use the Vorbis Comment column where the codec is supported; FLAC pictures additionally use native PICTURE metadata blocks. WavPack/Musepack and other supported APE-tagged formats use APEv2. WMA uses ASF. M4A/M4B/MP4 use the MP4 column. Matroska registrations remain unavailable. Tracker/module header fields, especially XM Tracker Name, use separate format-specific codecs noted in the row.

## Important distinctions

Year, Date, Release Date and Original Release Date are four independent identities. There is no Year extraction, date completion, cross-field synchronization or default copying. `©day` belongs to Year in this profile; Date and Release Date use distinct MP4 freeforms. Keeping these storage identities does not require exposing Date in the common-field Inspector; Date is an optional Inspector row in the current settings, not a required one.

Track Number, Total Tracks, Disc Number and Total Discs are four semantic components. The two members of each pair can share a physical location. `trackNumberText` and `discNumberText` carry formatting/edit intent, not additional public metadata fields. Historical private `AUDIOMATOR_*_TEXT` / `TAGLIBAUDIOMETADATA_*_TEXT` fields are recovery inputs only, never new UI fields or preferred write targets. Normal edited-pair recovery/retirement is internal and atomic; loading never cleans a file. See [numbering policy](../Architecture/METADATA_MAPPING_SPEC.md#61-total-tracks-and-total-discs-storage).

Content Group (`TIT1` / `©grp`), Grouping (`GRP1` / `F(GROUPING)`) and Work (`TXXX(WORK)` / `©wrk`) remain separate. Encoded By (`TENC` / `©enc`) and Encoder Settings (`TSSE` / `©too`) also remain separate. ITUNESADVISORY uses absent, 0, 1 and 2 as different states; false/zero is not absence. Unknown native advisory codes are preserved rather than relabeled as Clean or Unset.

MP4-exclusive fields are included in the same table, not hidden in another list. The Matroska TV Episode/TV Season targets are on those same rows with their different TargetTypeValue values and `[P]` markers. Tracker Name has no portable key in the seven core tag surfaces; its XM header route is an explicit exception. Artwork is a structured collection, not an ordinary string field.

## Meaning versus storage

The Purpose column paraphrases the linked primary documentation; it is not a claim that each standard uses AudioMator's exact naming. Date/Year separation, Content Group versus Grouping, unsupported writes and advisory presentation include AudioMator-specific policy. The application guide explicitly distinguishes those choices. Apple documents metadata identifiers but does not specify every opaque iTunes value encoding; no new encoding or writable codec is inferred here. TagLib is a mapping reference rather than an authority for undocumented binary semantics. Sound Check and encoder-padding data should be preserved, not manually invented. ReplayGain values describe playback analysis; this guide does not calculate them or change the audio.
